# Security and Confidentiality

## Do not post sensitive information publicly

This repository is public. Issues, pull requests, and comments may be visible to anyone.

Never post:
- passwords, API keys, tokens, cookies, or credentials;
- private source code;
- customer or personal data;
- proprietary datasets;
- private infrastructure details;
- trade secrets or confidential documents.

## Project inquiries

For a paid engagement, use the public intake form only for a **high-level, non-confidential description** of the problem.

If the engagement is accepted, a private channel should be established before sensitive technical material is exchanged.

## Suspected security issue

Do not publish exploit details or sensitive evidence in a public issue.

Open a minimal high-level issue stating that you need a private security communication channel, without including the vulnerability details themselves.
